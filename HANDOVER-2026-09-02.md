bespoke secret to invent. The ops app already holds `SUPABASE_SECRET_KEY` for its own project and

The one real question left is blast radius, and it should be stated plainly rather than dressed up:
a secret key can write **anything** in ThermoStat, so the review app would go from provably unable
to corrupt published data to trusted not to. That is a trade, not a flaw — the app already holds a
key with the same power over the ops database.

**Felix has to paste the key into Vercel.** We cannot: `vercel.env` holds only a deployment-
protection bypass token, not an API token. It is in Supabase → ThermoStat project → Settings → API.
