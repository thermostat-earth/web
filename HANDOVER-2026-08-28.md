The question left on the table, unanswered:

suppliers"* and moves **+1,952,000 tCO₂e, +38.5%**. Is improved visibility better measurement, or a

## Also unanswered

Felix asked: *"did we not already do an external check to build the business model review?"*

**Answered properly on Felix's prompting — the first answer was too narrow.** The machinery exists
and is well developed. `src/lib/review.ts` in the ops app holds a four-pass relevance assessment,
where passes 1 to 3 are evidence and only pass 4 is an opinion, plus a `business_model` panel whose
every claim carries sources and which counts unsourced claims so an unsourced assessment announces
itself rather than looking finished.

It has been exercised on **exactly one company: Inditex.** `data_review` holds a single row —
pipeline company 25, the demo account, 3 August. Its sources are **invented by design**, because it
is the ops-004 demo seed (see `supabase/ops-014-business-model-sources.sql`).

So: one worked example, on the company the whole reporting-basis problem was discovered through,
built with fictional sources for demo purposes.

Felix's own account has **zero** `data_review` rows. No real business-model review exists for any
company, H&M included. H&M does carry a relevance override on category 2 marked `not_required` — so
a judgement was made and only its conclusion kept, without reasoning, sources or a date. That
matters for the validity-range design, which needs a date to run from and has none.
